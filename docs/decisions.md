# Architecture Decision Log

Append-only. Each entry: `[ID] [date] [decision] — [reason] — [superseded-by: none | ID]`.
Superseded entries stay in the log with a pointer forward — this is a
history, not a current-state document. Read this before starting work on any
milestone; it's a handful of short lines, not the whole spec.

- **ADR-001** 2026-09-15 — Standalone Nx repo, own public GitHub repo, not folded into an existing monorepo — independent discoverability (own README, stars, issue tracker) matters more here than monorepo convenience for a portfolio artifact — superseded-by: none
- **ADR-002** 2026-09-15 — npm as the package manager, not pnpm or yarn — zero extra tooling required on a contributor's machine, and this workspace's scale doesn't need pnpm's workspace-linking performance — superseded-by: none
- **ADR-003** 2026-09-15 — Vitest as the test runner across the whole workspace, including `apps/web` — Angular CLI's own default for new workspaces as of Angular 21, confirmed against the live `@angular/build:unit-test` schema rather than assumed from memory — superseded-by: none
- **ADR-004** 2026-09-15 — Node 24, pinned via `.nvmrc` — current Active LTS as of this project's start; will move to 26 when that becomes Active LTS (~October 2026) — superseded-by: none
- **ADR-005** 2026-09-15 — Full v1 scope committed to (all 7 milestones, ~9–12.5 weeks), not a trimmed mechanical-only v1 — the verification gate is the actual differentiator against every existing AngularJS migration tool; cutting it ships a codemod script with a slower story — superseded-by: none
- **ADR-006** 2026-09-15 — Fixture repos locked in: `angular/angular-phonecat`, `mrholek/CoreUI-AngularJS`, `akveo/blur-admin`. All three directly license-checked (not assumed) — see `docs/product-spec.md §11` for the specific caveats on the latter two — superseded-by: none
- **ADR-007** 2026-09-15 — `gitleaks` named as the specific secrets-scanning tool, not "gitleaks or equivalent" — a coding agent implementing CI/pre-commit hooks needs one concrete tool to wire up, not an open choice to make later — superseded-by: none
- **ADR-008** 2026-09-15 — Provider rate limits (Groq/Gemini/OpenRouter) are not hardcoded as fact anywhere in the spec beyond priority order — direct verification against both providers' own docs during this project's setup showed the numbers already drifting from third-party trackers, and free-tier terms are each provider's unilateral policy per `docs/product-spec.md §7`. Priority order (Groq → Gemini Flash-Lite → Gemini Flash → OpenRouter) is fixed; exact RPM/RPD figures get checked at M3 build time, not copied from this log — superseded-by: none
- **ADR-009** 2026-09-15 — CI ships on day one with only the `secrets-scan` job active and passing. The rest of the pipeline in `docs/architecture.md §5` (lint, typecheck, unit tests, dependency-boundary check, fixture integration) gets added incrementally as each milestone lands the tooling it depends on — a red CI badge before there's a workspace to lint or build is worse than a small badge for now — superseded-by: none
- **ADR-010** 2026-09-15 — Inventory's registration scanner recognizes AngularJS 1.5+'s `.component(name, { controller, ... })` form alongside `.controller`/`.directive`/`.service`/`.factory`/`.filter` — found by actually running M0's scanner against the pinned `angular-phonecat` commit, which turned out to use `.component()` exclusively and would otherwise have been under-reported to zero controllers/directives on the project's own clean baseline fixture. Not a new codemod pattern (it still targets the same directive/`@Component` output as pattern #4 in `docs/product-spec.md §6.3`), just a detection gap in Stage 1 — superseded-by: none
- **ADR-011** 2026-09-15 — Vendored fixture repos under `fixtures/` are excluded from Nx's project inference (`exclude: ["fixtures/**"]` on all three plugin registrations in `nx.json`). Without it, Nx auto-detected the vendored `angular-phonecat` submodule as a lintable/buildable project and ran this workspace's own strict TypeScript ESLint rules against its 2013-era ES5 source, which was never the intent — fixture repos are scanned by migration-core, not linted as if they were our own code — superseded-by: none
- **ADR-012** 2026-09-15 — `npm audit` reports a high-severity advisory (`smol-toml` DoS on malformed TOML) as a transitive dependency of `nx` itself. Not remediated: the only fix path downgrades `nx` to 22.6.4, undoing the confirmed-current, confirmed-Angular-compatible version this project deliberately pinned (ADR context: §2 of `docs/architecture.md`). The vulnerable path requires parsing attacker-supplied TOML, which nothing in this project's own pipeline does — accepted as a known, tracked, low-relevance finding rather than silently ignored or worked around by downgrading — superseded-by: none
- **ADR-013** 2026-09-15 — M0's ingest module implements test-runner *detection* (Karma config presence, PhantomJS usage) and a pure *remediation generator* (`remediateKarmaConfig`), but does not itself install a browser, run Karma, or check an exit code. Actually executing a repaired test suite requires the sandboxed execution environment that Stage 4 owns (`docs/milestones/m2-verification.md`), which doesn't exist yet at M0. `docs/milestones/m0-inventory.md`'s original wording ("attempt remediation... mark untested") reads as if M0 does this end-to-end; it doesn't yet — the static half is built now, the execution half is M2's job, not deferred silently. (The generator's implementation approach is superseded by ADR-014 — this entry's scope decision, detection-and-generation-only, still stands.) — superseded-by: none
- **ADR-014** 2026-09-15 — `remediateKarmaConfig` and its detection counterpart rewritten from regex/text-substitution to AST-based (parse the config, edit only the `browsers` array's actual elements). The regex version was a real, demonstrated bug: `/PhantomJS(?=[\s,\]])/g` had no left-boundary check, so a config containing an unrelated identifier like `usePhantomJS` could have its declaration renamed but not its reference (or vice versa), producing broken JS — and separately, matching PhantomJS as a bare substring anywhere in the file (not scoped to the `browsers` array) meant a comment or a `customLaunchers` entry could trigger a false positive or get silently rewritten. Found via adversarial review, not by a failing test — the original regex version's own test suite only checked that the string "PhantomJS" disappeared, not that nothing else changed — superseded-by: none
- **ADR-015** 2026-09-15 — `REGISTRATION_KINDS` expanded from the original five methods (`controller`/`directive`/`service`/`factory`/`filter`, later plus `component` per ADR-010) to the full named-registration surface of `angular.Module`: `provider`, `value`, `constant`, `decorator`, `animation` added. Root cause, not a one-off patch: a hardcoded "the methods I've personally seen so far" list had already missed `.component()` once (ADR-010); an adversarial review flagged that the same failure mode would keep recurring against M1's real-world fixtures (`CoreUI-AngularJS`, `blur-admin`) unless the list matched the actual API instead of accumulated observation. `.config()`/`.run()` deliberately excluded — they take only a function, no name, so they don't fit `RegistrationEntry`'s shape; `.config()` blocks are scanned separately for their contents by scan-routes.ts — superseded-by: none
- **ADR-016** 2026-09-15 — `secrets-scan`'s pattern matching rewritten to find all matches in one pass and skip a later pattern's match if it overlaps an earlier one's character range, rather than running each of the 8 patterns fully independently. Two patterns could legitimately both match the same real secret (`API_KEY="..."` matches both `generic-api-key-assignment` and `env-style-secret-line`), which double-counted it in `scanForSecrets` and, in `redact`, caused the second pattern's replace pass to match and re-redact the first pattern's already-redacted `[REDACTED:...]` placeholder — losing the correct attribution and corrupting the output. Found by adversarial review, confirmed with a regression test before the fix, not assumed impossible — superseded-by: none
- **ADR-017** 2026-09-15 — `.gitleaks.toml`'s allowlist narrowed from a blanket `.*\.spec\.ts$` (every spec file in the repo) to the three exact file paths that actually embed fake test credentials. The broad version was flagged independently by two review angles as a real security-relevant scope bug: per `CLAUDE.md`'s own gitleaks-hygiene rule, a real credential accidentally pasted into any *other* spec file anywhere in the repo — including a future one — would have been silently exempted by filename pattern alone. Exact-path scoping means only the files that need the exemption get it — superseded-by: none
- **ADR-018** 2026-09-15 — `libs/migration-core/src/inventory` recognizes vendored AngularJS framework source by its official `@license AngularJS v...` build banner and excludes it from the inventory report (surfaced as a new `vendoredFilesSkipped` count, not silently dropped). Found by actually running the scanner against `angular-phonecat` after installing its own dependencies: its build step copies `angular.js`/`angular-route.js`/`angular-animate.js`/etc. into `app/lib/`, and without this filter the scanner reported Angular's own internal `$compile`/`$animate`/`ngView` registrations as if they were the app's code — inflating every count in exactly the way this project's "honest numbers" positioning argues against. Directory-name conventions for vendored code vary too much to filter on reliably beyond the two package-manager-standard ones (`node_modules`, `bower_components`) already excluded; the license banner is a precise, low-false-positive content signal instead — superseded-by: none
- **ADR-021** 2026-09-15 — `scaffoldTargetWorkspace` always runs `ng new` with `cwd` set to the target output directory's *parent* and only the basename passed to `--directory`, never the full absolute path in `--directory` itself. Found by actually running the real command against a real absolute scratch path (PLAN-m0.5-scaffold.md's Phase 2 manual verification, not assumed from the generator's exit code): `ng new <name> --directory <absolutePath>` exits 0 but silently strips the leading `/` and nests the generated workspace under whatever the process's own cwd happened to be, instead of erroring or honoring the absolute path — confirmed reproducible both through the CLI wrapper and by running the raw `npx @angular/cli new` command directly. Re-verified fixed by re-running for real after the change: workspace landed at the exact requested absolute path, `ng build` exited 0, and `dist/<name>/browser/` contained real build output — superseded-by: none
- **ADR-020** 2026-09-15 — Re-verified before M0.5: Nx 23.2.1 / Angular / Node 24 / TypeScript ~6.0.3 combination still holds, with one correction to the assumed target. Angular's actual latest stable (checked against the live npm registry, not cached docs) is 22.1.x, not 21.x — `@angular/compiler-cli@22.1.6`'s published `peerDependencies` require `typescript: ">=6.0 <6.1"`, which this repo's pinned `~6.0.3` satisfies exactly. `@nx/angular@23.2.1`'s peer range (`@angular-devkit/build-angular >=20.0.0 <23.0.0`) covers Angular 22. `@angular/cli@22.1.8` requires Node `^22.22.3 || ^24.15.0 || >=26.0.0`; local Node is 24.19.0, which satisfies it, but `.nvmrc`'s bare `24` only guarantees compatibility if contributors keep their Node 24 install reasonably current — worth a note if this ever bites someone on an older 24.x patch. Two secondary sources (Context7's cached Nx docs, an AI-summarized fetch of `angular.dev/reference/versions`) both reported Angular 21 as current and were wrong by a full minor lag versus the npm registry — registry `peerDependencies` is the source of truth here, not a docs page's cache age. M0.5 scaffolds against Angular 22.x, not 21.x — superseded-by: none
- **ADR-019** 2026-09-15 — Two things found during the same adversarial review pass are deliberately *not* fixed, and are recorded here so they read as considered decisions rather than gaps nobody noticed: (1) `scan-routes.ts`/`scan-watches.ts` match a call's receiver by source text (`$routeProvider`, `$scope`), not by resolving the identifier through DI to confirm the binding, so a locally-aliased receiver (`function (rp) { rp.when(...) }`) is missed — real AngularJS code overwhelmingly keeps DI parameter names matching the injected token, making this a low-prevalence false negative, not worth the meaningfully larger scope-resolution analysis it would take to close. (2) Each `scan-*.ts` file still runs its own traversal of the parsed project (deduplicated to share one `forEachPropertyAccessCall` helper, but still four separate passes) rather than one combined pass dispatching to four handlers — a real ~4x CPU opportunity on a large repo, deferred until M1's larger fixtures actually show it mattering, since combining them now would cost the four scanners' current independent testability for a gain that doesn't show up at M0's demonstrated (15-file, sub-second) scale — superseded-by: none
