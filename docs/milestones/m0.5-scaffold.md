# M0.5 — Target Workspace Scaffold

**Status:** done — see [PR #3](https://github.com/AshwinSathian/angularjs-migration-copilot/pull/3), `docs/decisions.md` ADR-020–022
**Estimate:** 2–3 days
**Depends on:** M0

## Scope

Generate a real Angular workspace, via the actual Angular CLI, into a separate output directory — never in-place over the source repo. Per [product-spec.md §6.2a](../product-spec.md), this is what makes Stage 4's `tsc --noEmit` mean anything later: compiling a single migrated file in isolation, with no real `angular.json`/module graph/decorator context around it, doesn't verify anything.

- Before generating anything, check Nx's current Angular-version compatibility notes at `nx.dev` — Nx's Angular support sometimes trails the newest Angular release by a point version, and the spec deliberately didn't pin an exact combination for this reason. See [architecture.md §2](../architecture.md).
- The source tree stays read-only for the entire pipeline: a failed or partial scaffold run must never leave the original repo in a broken state.
- This step has to complete before any Stage 2 file-level transform begins.

## Definition of done

The generated workspace actually builds with `ng build` — run and confirmed, not assumed from the generator's own exit code.
