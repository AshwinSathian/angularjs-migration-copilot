# M0 — Inventory Scanner

**Status:** implementation complete, adversarially reviewed, awaiting your final sign-off
**Estimate:** 1–2 weeks
**Depends on:** nothing — this is the first milestone

## Scope

A full AST scan of a target AngularJS repo, producing a dependency graph. Report-only — no transforms happen here.

- Detect AngularJS version, build tooling (Gulp/Grunt/Webpack/none), and test runner, per [product-spec.md §6.1](../product-spec.md). **Shipped:** `libs/migration-core/src/ingest/`.
- If a test runner is detected, check whether its `browsers` array references PhantomJS — structurally, via AST, not a whole-file text match — and generate a remediated config swapping it for ChromeHeadless. **Scope note:** this milestone builds detection and a pure AST-based remediation generator, not execution — actually running the repaired suite and checking its exit code needs Stage 4's sandbox, which doesn't exist until M2. `TestRunnerDetection` therefore has no "tested"/"untested" verdict field: `usesPhantomJs` is a static signal about one specific known failure mode, not a substitute for actually running the suite. Conflating the two would be exactly the kind of unverified claim this project's own philosophy argues against. See [decisions.md ADR-013](../decisions.md).
- Scan controllers, directives, components, services, factories, providers, values, constants, filters, decorators, animations, route definitions, and `$scope.$watch` usage with ts-morph, per [product-spec.md §6.2](../product-spec.md). **Shipped:** `libs/migration-core/src/inventory/`. (ng-morph isn't used yet — ts-morph alone was sufficient for this milestone's AST queries; revisit if a later milestone's transforms need ng-morph's Angular-specific helpers.)
- Secrets scan (`libs/secrets-scan`) runs here too, wired into ingest. **Shipped.**
- Due-diligence pass on the three fixture repos: `angular/angular-phonecat` is vendored as a pinned git submodule (`fixtures/angular-phonecat`, commit `ef6f6eb`). Actually verified, not assumed: `npm install` succeeds on Node 24 (pinned via the sibling `fixtures/angular-phonecat.nvmrc` — not inside the submodule itself, since that would require a commit the upstream remote doesn't have), and the real Karma suite passes 5/5 specs against a real, current Chrome. `mrholek/CoreUI-AngularJS` and `akveo/blur-admin` are **not vendored yet** — deferred to M1, since that's the milestone that actually needs their (messier, more period-specific) tooling exercised.

## What actually shipped

- `libs/secrets-scan` — pattern-based secret detection and redaction (`scanForSecrets`, `redact`), with a single non-overlapping-match pass shared by both (an earlier version scanned per-pattern independently, which double-counted and mis-attributed matches that two patterns could both reasonably claim, e.g. `API_KEY="..."`).
- `libs/migration-core/src/ingest/` — AngularJS version detection, build-tool detection, structural (AST-based, not text-substring) Karma/PhantomJS detection and remediation, and the repo-wide secrets scan.
- `libs/migration-core/src/inventory/` — module declarations; controller/directive/component/service/factory/provider/value/constant/filter/decorator/animation registrations with DI dependency extraction (including ES6 shorthand-method controllers); ngRoute/ui-router route definitions; `$watch`/`$watchCollection`/`$watchGroup` usage; and detection of vendored AngularJS framework source (by its official `@license AngularJS` build banner) so a repo that copies its own dependencies in-tree doesn't get the framework's internals reported as if they were the app's own code.
- `libs/migration-core/src/cli.ts` — an `inventory <repoPath>` CLI command wiring ingest + inventory together into one JSON report.
- 84 unit tests, all passing; lint, typecheck, and build clean across both libraries.

## Adversarial review round

Before calling this done, the diff went through an 8-angle adversarial review (line-by-line, removed-behavior, cross-file, reuse, simplification, efficiency, altitude/root-cause, conventions) plus a manual pass. Real issues found and fixed, not just noted:

- **The Karma/PhantomJS remediation was regex-based text substitution, not AST-based.** It could rename an unrelated identifier that happened to contain the word "PhantomJS" (e.g. `usePhantomJS`), producing broken JS, and could touch `customLaunchers` entries it had no business touching. Rewritten to parse the config and edit only the `browsers` array's actual string-literal elements — the same standard the rest of this codebase already holds itself to.
- **The registration-method list was a hardcoded five methods**, missing `.component()` until a real fixture run found the gap (ADR-010), then found to still be missing `.provider()`/`.value()`/`.constant()`/`.decorator()`/`.animation()` on the same root-cause reasoning. Now derived from one `REGISTRATION_KINDS` constant matching AngularJS's actual `angular.Module` API surface, not "the methods I've personally seen so far."
- **Two secret patterns could both match the same real secret** (`API_KEY="..."` matches both `generic-api-key-assignment` and `env-style-secret-line`), double-counting it in reports and re-redacting an already-redacted placeholder. Fixed with a single non-overlapping-match pass.
- **The gitleaks allowlist was scoped to every `*.spec.ts` file in the repo**, not just the specific tests that legitimately embed fake credentials — a real secret pasted into any other spec file anywhere in the codebase would have been silently exempted. Narrowed to the three exact files that need it.
- **A genuine self-inflicted regression, caught by the test suite doing its job:** parallelizing file reads into `ts-morph` (a real efficiency fix) initially broke `createSourceFile` outright — it refuses to run against a path that already exists on real disk without `overwrite: true` — and the surrounding `try/catch` silently swallowed the error, making the inventory scanner report zero files. The existing tests failed immediately; fixed and now documented in the code as exactly what that catch block must never hide again.
- **Running the fixed scanner against the real fixture found a scanner bug the fixture itself couldn't have revealed through unit tests alone:** after installing `angular-phonecat`'s own dependencies (to verify the `npm install` claim below), its build step copies AngularJS's own framework source into `app/lib/`. Without a filter, the scanner reported Angular's internal `$compile`/`$animate`/`ngView` registrations as if they were the app's own code — inflating every count. Fixed by recognizing AngularJS's official `@license AngularJS` build banner and excluding vendored framework files, surfaced honestly via a new `vendoredFilesSkipped` field rather than silently dropped.
- Documented, not fixed: `scan-routes.ts` and `scan-watches.ts` match a call's receiver by source text (`$routeProvider`, `$scope`), not by resolving the identifier back through DI to confirm the binding — a locally-aliased receiver (`function (rp) { rp.when(...) }`, `var scope = $scope`) is missed. Real-world AngularJS code overwhelmingly keeps DI parameter names matching the injected token, so this is a deliberate, documented scope line, not a silent gap.
- Documented, not fixed: each of the four `scan-*.ts` files still does its own traversal of the parsed project (now via one shared `forEachPropertyAccessCall` helper, which fixed the *duplication*, not the *count* of traversals). Merging all four into a single combined pass would cut inventory-scan CPU roughly 4x on a large repo, but would also make each scanner harder to test in isolation — deferred until M1's larger fixtures (`CoreUI-AngularJS`, `blur-admin`) show this actually mattering, rather than optimized against a 15-file baseline that runs in milliseconds either way.

## Verified against the real fixture

Ran against the real, pinned `angular-phonecat` fixture, on a clean checkout (no installed dependencies, no generated files): 5 modules, 5 registrations (1 `.animation()`, 2 `.component()` with correct DI, 1 filter, 1 factory), 2 ngRoute routes, 0 `$watch` usages, 0 secrets, 0 vendored files skipped, AngularJS 1.8.x detected from `package.json`, Karma detected with no PhantomJS.

Every entry in that output has been cross-checked by hand against the actual source — not "the JSON looks reasonable." Specifically: `grep` confirmed there are genuinely no bare `.controller(`/`.directive(` calls at this commit (it uses `.component()` exclusively); each `.component()`'s reported DI list was checked against its actual `controller: [...]` array; the `.animation('.phone', ...)` entry was checked against `app/app.animations.js` directly; `karma.conf.js` was read directly to confirm `browsers: ['Chrome', 'Firefox']` with no PhantomJS reference.

## Definition of done

Produces a correct report against `angular/angular-phonecat`, checked by a human against the repo's actual structure — not "the JSON output looks reasonable." Concretely, before calling this done: open `fixtures/angular-phonecat/app/` yourself, pick at least the `.component()` and `.animation()` entries above, and confirm their reported names and dependencies match what's actually in those files. The cross-check above was done once, by the same process that wrote the scanner — per this milestone's own standard, self-certification isn't the second, independent look this is supposed to get.
